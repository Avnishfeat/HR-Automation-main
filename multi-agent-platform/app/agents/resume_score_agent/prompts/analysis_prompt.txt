## STEP-BY-STEP ANALYSIS PROCESS

### STEP 1: EXTRACT PROFESSIONAL EXPERIENCE

**Rules for experience_years calculation:**
- ONLY count full-time professional roles (W2, FTE, or long-term contracts)
- DO NOT count internships (track these separately)
- For each professional role, calculate duration in years with decimals
  - Example: 2 years 3 months = 2.25 years
  - Example: 1 year 6 months = 1.5 years
  - Example: 8 months = 0.67 years
- Sum all professional role durations to get experience_years
- If dates overlap, use the non-overlapping portion only
- "Present" means current date (November 2025)

**Extraction format:**
- Role 1: [Company] - [Title] - [Start Date] to [End Date] = X.XX years
- Role 2: [Company] - [Title] - [Start Date] to [End Date] = X.XX years
- Total: experience_years = X.XX

### STEP 2: COUNT PROJECTS FROM DEDICATED SECTION

**Rules for project_count calculation:**
- Look for a section explicitly titled: "PROJECTS", "PERSONAL PROJECTS", "PORTFOLIO", "PROJECT WORK", or similar
- Count ONLY projects listed under this dedicated section
- If NO such section exists → project_count = 0
- Projects mentioned in work experience, summary, or objective sections DO NOT count
- Each distinct project = 1 count

**Validation:**
- If you found a projects section, list each project name
- If no projects section exists, explicitly state: "No dedicated projects section found, project_count = 0"

### STEP 3: COUNT INTERNSHIPS

**Rules for internship_count calculation:**
- Count roles explicitly labeled: "Intern", "Internship", "Co-op", "Virtual Internship", "Summer Intern"
- Each distinct internship = 1 count
- If a candidate had 2 internships at same company, count as 2
- DO NOT include these in experience_years

### STEP 4: EXTRACT JD REQUIREMENTS

**From the job description, identify:**

1. **Required Experience:**
   - Minimum years required (if mentioned)
   - Type of experience needed
   - Specific roles or responsibilities

2. **Required Technical Skills:**
   - Programming languages
   - Frameworks and libraries
   - Tools and platforms
   - Databases
   - Cloud technologies
   - Other technical requirements

3. **Required Domain Knowledge:**
   - Industry experience
   - Specific domain expertise
   - Business understanding

4. **Preferred Qualifications:**
   - Education requirements
   - Certifications
   - Soft skills
   - Additional nice-to-have skills

### STEP 5: MATCH RESUME AGAINST JD REQUIREMENTS

**A. Experience Match:**
- Does candidate meet minimum experience requirement?
- Is their experience relevant to the JD?
- Calculate experience_match_percentage:
  - If JD requires X years and candidate has >= X years of relevant experience: 100%
  - If candidate has < X years: (candidate_years / required_years) * 100%
  - If no experience requirement specified: Judge based on role level implied by JD

**B. Skills Match:**
- For EACH required skill in JD, check if present in resume:
  - Direct mention: "Python", "React", "AWS" → Skill present
  - Implicit usage: "Built REST API with Django" → Python present
  - Project demonstration: "Deployed on AWS Lambda" → AWS present
  - No evidence → Add to missing_keywords
- Calculate skills_match_percentage:
  - skills_match_percentage = (skills_present / total_required_skills) * 100%

**C. Project Relevance:**
- Do the candidate's projects demonstrate JD requirements?
- Are projects technically complex?
- Do projects show practical application of required skills?

**D. Overall Quality Indicators:**
- Education alignment with JD
- Relevant certifications
- Measurable achievements
- Domain expertise
- Leadership experience (if required)

### STEP 6: CALCULATE MATCH SCORE (0-100)

**Use this EXACT formula:**

```
Step 1: Calculate component scores

experience_score = experience_match_percentage * 0.40
skills_score = skills_match_percentage * 0.35
project_score = (project relevance assessment 0-100) * 0.15
quality_score = (quality indicators assessment 0-100) * 0.10

Step 2: Sum all scores

match_score = experience_score + skills_score + project_score + quality_score

Step 3: Round to 1 decimal place

Final match_score (cap at 100.0)
```

**Component Assessment Guidelines:**

**Experience Score (40 points max):**
- 100% relevance: Full points
- 70-99% relevance: Proportional points
- Below 70% relevance: Proportional with penalty

**Skills Score (35 points max):**
- 100% match: 35 points
- 90-99% match: 32-34 points
- 80-89% match: 28-31 points
- 70-79% match: 24-27 points
- Below 70%: Proportional

**Project Score (15 points max):**
- Highly relevant projects demonstrating required skills: 13-15 points
- Moderately relevant projects: 8-12 points
- Basic/learning projects: 4-7 points
- No relevant projects: 0-3 points

**Quality Score (10 points max):**
- Relevant education: +3 points
- Certifications matching JD: +2 points
- Measurable achievements: +3 points
- Domain expertise: +2 points

### STEP 7: DETERMINE ELIGIBILITY

**Apply this simple rule:**

```
IF match_score >= 40:
    → is_eligible = true
    
ELSE:
    → is_eligible = false
```

**Rationale:**
- Score 40+ means candidate meets minimum threshold for JD requirements
- Score below 40 means significant gaps exist

### STEP 8: IDENTIFY MISSING KEYWORDS

**Rules for missing_keywords:**
- List ALL required technical skills from JD that have ZERO evidence in resume
- Include only skills that are explicitly required (not nice-to-have)
- Be specific: "React.js", "AWS Lambda", "PostgreSQL" (not generic terms like "frontend")

### STEP 9: IDENTIFY KEY STRENGTHS

**Rules for key_strengths (2-4 items):**
- Must be SPECIFIC (not "good communicator" or "hard worker")
- Must be RELEVANT to this specific job
- Must be EVIDENCE-BASED (cite from resume)
- Focus on areas where candidate EXCEEDS or MATCHES JD requirements

**Examples:**
- "5+ years experience with Python and Django, exceeding JD requirement of 3 years"
- "Built 4 production-grade full-stack applications demonstrating required React and Node.js skills"
- "Proven AWS expertise with 3 years managing cloud infrastructure at scale"
- "Domain expertise in fintech with specific experience in payment processing systems as required"
- "Led team of 6 engineers, matching leadership requirement in JD"

### STEP 10: WRITE JUSTIFICATION

**Structure (4-6 sentences):**

1. **Experience Assessment**: State candidate's experience vs JD requirement
2. **Skills Coverage**: Percentage match, highlight critical gaps if any
3. **Project Portfolio**: Quality and relevance of projects to JD
4. **Strengths & Gaps**: Specific areas of strength and notable gaps
5. **Overall Fit**: Summary of how well candidate matches JD
6. **Recommendation**: Clear hiring recommendation aligned with is_eligible

**Tone:**
- Be factual and objective
- Use specific numbers and percentages
- Highlight both strengths and gaps
- Align recommendation with eligibility decision
